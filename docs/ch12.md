# 第十二章：声明文件与类型空间

> **本章目标**：理解 `.d.ts` 声明文件的作用；会通过 DefinitelyTyped 安装 `@types` 包；能编写简单的自定义声明文件；了解三斜线指令的适用场景。

## 什么是声明文件（.d.ts）

纯 JavaScript 库本身没有类型信息，但很多现代库会在包内自带 `.d.ts` 类型定义，不需要额外安装。对于没有内置类型的库，TypeScript 通过**声明文件**（Declaration File，扩展名 `.d.ts`）来添加类型描述。这样你在 TS 中导入 JS 库时，就能获得类型检查和自动补全。

```typescript
// 假设你安装了一个纯 JS 库 "lodash"，但没有对应的类型定义：
import _ from "lodash";   // 编译期直接报错 TS2307：找不到模块 "lodash" 的类型声明
_.chunk([1, 2, 3, 4], 2); // 更谈不上参数和返回值的类型检查
```

安装 `@types/lodash` 后（见「DefinitelyTyped 与 @types」），错误消失，`_.chunk` 的参数和返回值都能获得类型检查。

## DefinitelyTyped 与 @types

社区维护了一个巨大的声明文件仓库 [DefinitelyTyped](https://github.com/DefinitelyTyped/DefinitelyTyped)，包含数万个流行 JS 库的类型定义。通过 npm 安装对应的 `@types` 包即可：

```bash
# 安装 lodash 的类型定义
npm install -D @types/lodash

# 安装 express 的类型定义
npm install -D @types/express

# 安装 node 的全局类型定义（用于 Node.js 项目）
npm install -D @types/node
```

安装后，通过 `import` 使用的模块类型（如 `@types/lodash`）会被自动识别，无需额外配置。但要注意：**TypeScript 6.0 起 `types` 选项默认是 `[]`**，因此提供**全局**类型的包（如 `@types/node` 的 `process`、`Buffer`）不会自动加载，需要在 `tsconfig.json` 中显式配置 `"types": ["node"]`（见附录 A）——只通过 `import` 使用的类型不受此影响。

## 自己编写声明文件

当你使用一个没有 `@types` 包的 JS 库时，可以自己编写声明文件：

```typescript
// types/my-lib.d.ts
declare module "my-lib" {
  export function doSomething(x: string): number;
  export interface Config {
    timeout: number;
    retries: number;
  }
}
```

或者在项目中创建一个 `*.d.ts` 文件来声明全局类型：

```typescript
// global.d.ts
declare global {
  interface Window {
    myAppConfig: { apiUrl: string };
  }
}

export {};  // 确保文件被当作模块
```

## 三斜线指令（Triple-Slash Directives）

早期 TS 项目用三斜线指令来引用声明文件，现在已不常用（npm + `@types` 更主流）：

```typescript
/// <reference types="node" />
/// <reference path="./my-lib.d.ts" />
```

> **实践建议**：优先查找 `@types` 包；没有的话自己写 `.d.ts`；三斜线指令仅在特殊场景使用。

## 本章练习

### 练习 1：为无类型库编写声明文件（重要程度 ⭐⭐⭐）

某个纯 JS 库 `my-lib` 提供 `doSomething(x: string): number`，请为它编写 `my-lib.d.ts` 声明文件，并说明之后如何导入使用。

::: details 查看答案
```typescript
// my-lib.d.ts
declare module "my-lib" {
  export function doSomething(x: string): number;
  export interface Config {
    timeout: number;
    retries: number;
  }
}
```
之后即可正常导入并获得类型检查：

```typescript
import { doSomething } from "my-lib";
doSomething("x");  // 类型为 number
```
:::

### 练习 2：理解 `@types`（重要程度 ⭐⭐⭐）

使用没有自带类型的 `lodash` 时，如何获得类型检查？为什么 TS 6.0+ 下有些 `@types` 需要额外配置？

::: details 查看答案
```bash
npm install -D @types/lodash
```
- `@types/lodash` 提供模块类型，`import _ from "lodash"` 之后 `_.chunk(...)` 等就有类型了
- 但 TS 6.0+ 的 `types` 默认是 `[]`：**全局**类型的包（如 `@types/node` 的 `process`、`Buffer`）不会自动加载，需要在 tsconfig 显式配置 `"types": ["node"]`；通过 `import` 使用的模块类型不受此限制
:::

### 练习 3：全局类型声明（重要程度 ⭐⭐）

想在 `window` 上挂一个 `myAppConfig` 全局配置，如何声明？注意声明文件需要是模块还是脚本？

::: details 查看答案
```typescript
// global.d.ts
declare global {
  interface Window {
    myAppConfig: { apiUrl: string };
  }
}

export {};  // 必须有 import/export 使文件成为"模块"，declare global 才能生效
```
之后 `window.myAppConfig.apiUrl` 就有类型了。
:::
