# 第三章：快速 JS 补课

> **本章目标**：快速掌握 JavaScript 中与 TS 学习直接相关的概念——`let`/`const`、基本类型、模板字符串、箭头函数、`===`、对象字面量、数组、解构赋值。
> 对已有编程基础的同学，这里只讲 JS 独特的地方，不讲什么是变量/循环/函数。

## 前置知识：JS 特有的概念

在开始之前，先了解几个 JS 特有的概念，它们在其他语言中不太常见：

**Hoisting（变量提升）**：JS 引擎在执行代码前，会先把 `var` 和 `function` 声明"提升"到作用域顶部。这意味着你可以在声明之前使用它们（值为 `undefined`）。`let` 和 `const` 也会进入作用域，但在声明语句执行前处于**暂时性死区**（TDZ），不能像 `var` 那样在声明前读到 `undefined`。

```javascript
// 以下是 JavaScript 行为示例（不是 TS 推荐写法）
console.log(a);  // undefined（var 被提升了，但值是 undefined）
var a = 1;

console.log(b);  // ReferenceError: Cannot access 'b' before initialization
let b = 2;       // let/const 有 TDZ，声明前访问会报错
```

**闭包（Closure）**：函数可以"记住"它被创建时的词法环境。即使外部函数已经返回，内部函数仍然可以访问外部函数的变量。

```typescript
function makeCounter() {
  let count = 0;  // 这个变量被闭包"捕获"
  return {
    increment: () => ++count,
    getCount: () => count,
  };
}
const counter = makeCounter();
counter.increment();  // 1
counter.increment();  // 2
counter.getCount();   // 2 —— count 变量仍然存在
```

**原型链（Prototype Chain）**：JS 对象通过原型（prototype）实现继承，而不是像 Java/C++ 那样的类继承。每个对象都有一个隐藏的内部属性 `[[Prototype]]`，它指向另一个对象（该对象的"原型"）；访问一个不存在的属性时，JS 会沿这条链向上查找，直到找到或到达 `null`。`__proto__` 是设置原型的传统写法（现代更推荐 `Object.getPrototypeOf` / `Object.setPrototypeOf`）：

```javascript
const animal = { eats: true };
const rabbit = { jumps: true };

rabbit.__proto__ = animal;   // 把 animal 设为 rabbit 的原型

console.log(rabbit.jumps);   // true（自有属性）
console.log(rabbit.eats);    // true（rabbit 没有 eats，沿原型链从 animal 找到）

// 原型链可以很长：longEar → rabbit → animal → Object.prototype → null
const longEar = { earLength: 10, __proto__: rabbit };
console.log(longEar.eats);   // true（沿链一路向上查找到 animal）
```

原型继承有几个关键行为：

- **写入不使用原型**：读取才沿链查找，**写入/删除永远直接作用于对象本身**。所以 `rabbit.walk = ...` 不会改到 `animal.walk`。
- **`this` 不受原型影响**：即使方法是从原型继承来的，调用时 `this` 仍然是点号前的对象（这一点与直觉相反，是经典考点）。
- **`for..in` 会遍历继承的属性**，而 `Object.keys` 只返回自有属性。用 `obj.hasOwnProperty(key)` 可判断属性是否属于对象自身。
- **⚠️ 共享陷阱**：原型上的**引用类型属性**（如数组）会被所有继承者共享：

```javascript
const hamster = { stomach: [], eat(food) { this.stomach.push(food); } };
const speedy = { __proto__: hamster };
const lazy = { __proto__: hamster };

speedy.eat("apple");
console.log(lazy.stomach);   // ["apple"] —— 两只仓鼠共享了同一个胃！
// 修复：每个对象自己持有状态（stomach: []），或在 eat 里赋值而不是 push
```

ES6 的 `class extends` 只是这套原型机制的语法糖——理解原型链，就能理解为什么 `this` 在继承中表现如此、方法是怎么被"找到"的。在 TypeScript 中，`class` 编译后生成的仍然是原型链。详见 zh.javascript.info 的[原型继承](https://zh.javascript.info/prototype-inheritance)。

**事件循环（Event Loop）**：JS 是单线程的，但通过事件循环实现异步。引擎在一个无限循环中"执行任务 → 休眠 → 等待新任务"。所有待执行的工作进入**任务队列**：

- **宏任务（macrotask）**：整个 `<script>`、事件回调、`setTimeout`/`setInterval` 回调等。按先进先出顺序执行；引擎执行一个宏任务期间**不会渲染**页面（所以超长任务会阻塞界面）。
- **微任务（microtask）**：`Promise.then/catch/finally`、`await` 之后的代码、`queueMicrotask` 回调。**每个宏任务结束后，会立刻清空整个微任务队列**，再处理下一个宏任务或渲染。

```javascript
setTimeout(() => console.log("timeout"));   // 宏任务，最后执行

Promise.resolve().then(() => console.log("promise"));  // 微任务，其次执行

console.log("code");   // 同步代码，最先执行
// 实际输出顺序：code → promise → timeout
```

顺序背后的逻辑：同步代码先跑完；之后引擎先清空微任务队列（`promise`），最后才轮到宏任务队列里的 `setTimeout` 回调。

> 💡 **与 TypeScript 的关系**：TS 的 `async/await` 最终编译为 Promise 链，其"之后"的代码都走微任务队列。理解了宏任务/微任务的顺序，就能解释 `await` 后的代码为什么总在同步代码之后执行、以及多个 Promise 的完成顺序。更完整的讲解见 zh.javascript.info 的[事件循环：微任务和宏任务](https://zh.javascript.info/event-loop)。

## 变量声明

```typescript
let x = 10;    // 可变变量（对应其他语言的 var）
const y = 20;  // 不可变变量（对应 final/const）
```

- `let` 是块级作用域（block-scoped），类似于其他语言的局部变量
- `const` 也是块级作用域，且声明后不能重新赋值
- **不要使用 `var`**（它是函数级作用域，有 hoisting 问题，现代 JS 不推荐使用）

> ⚠️ **`const` 不等于"深度不可变"**：`const` 只保证变量不能重新赋值，但对象/数组的内容仍然可以修改：
>
> ```typescript
> const user = { name: "Alice" };
> user.name = "Bob";  // OK——修改对象属性
> // user = { name: "Tom" };  // Error——不能重新赋值
> ```
>
> 如果需要深度不可变，可以用 `as const`（见第四章）或 Object.freeze()。

对比其他语言：

```typescript
// Java: int x = 10;
// Python: x = 10
// TS: let x: number = 10; （或简写为 let x = 10;，类型会自动推导）
```

## 基本类型

```typescript
{
  const name: string = "Alice";
  const age: number = 25;       // 没有 int/float 之分，都是 number
  const isOk: boolean = true;   // 小写！不是 Boolean
  const nothing: null = null;
  const notDefined: undefined = undefined;
}
```

> ❗ **重要**：类型名是小写 `string`、`number`、`boolean`，不是 `String`、`Number`、`Boolean`。大写版本是特殊的内置类型，几乎用不到。

## 模板字符串

用反引号代替引号，`${}` 嵌入表达式：

```typescript
{
  const name = "World";
  const greeting = `Hello ${name}, 2 + 3 = ${2 + 3}!`;
  console.log(greeting); // Hello World, 2 + 3 = 5!
}
```

对比 Python: `f"Hello {name}"`
对比 Java: `"Hello " + name`

## 箭头函数

```typescript
// 传统函数
function add(a: number, b: number): number {
  return a + b;
}

// 箭头函数（相当于 lambda）
const addArrow = (a: number, b: number): number => a + b;

// 多行的箭头函数需要花括号 + return
const addArrowMulti = (a: number, b: number): number => {
  const result = a + b;
  return result;
};

// 只有一个参数时可以省略括号（但标注类型时仍需括号）
const double = (n: number): number => n * 2;
// 无类型注解时：
// const double = n => n * 2;
```

对比 Python: `lambda a, b: a + b`
对比 Java: `(a, b) -> a + b`

## 严格相等 `===`

JS 中有 `==` 和 `===` 两种相等运算符：

```typescript
// TypeScript 会阻止不同类型间的直接比较（因为这种比较通常是逻辑错误）：
// @ts-expect-error —— TS 不允许 number 和 string 直接比较
5 == "5";   // JS 运行结果: true  （隐式类型转换后比较）
// @ts-expect-error —— TS 不允许 number 和 string 直接比较
5 === "5";  // JS 运行结果: false （类型不同直接返回 false）
```

**始终使用 `===` 和 `!==`**，除非你明确知道自己在做什么。

## 对象字面量

```typescript
const user = {
  name: "Alice",
  age: 25,
  greet() {        // 简写方法（相当于 greet: function() { ... }）
    console.log(`Hi, I'm ${this.name}`);
  }
};

// 访问属性
console.log(user.name);   // Alice
console.log(user["name"]); // 也可以用字符串键访问
```

对比 Java: 需要先定义 class，再 new 实例
对比 Python: dict 类似但属性访问用 `[]`

## 数组

```typescript
const nums: number[] = [1, 2, 3];
// 或 const nums: Array<number> = [1, 2, 3];

// 常用方法
nums.push(4);                    // 末尾添加
nums.pop();                      // 末尾删除
nums.forEach((n) => console.log(n)); // 遍历
const doubled = nums.map((n) => n * 2); // 映射（返回新数组）
const evens = nums.filter((n) => n % 2 === 0); // 过滤
```

## 解构赋值

```typescript
// 对象解构
{
  const user = { name: "Alice", age: 25 };
  const { name, age } = user;      // 提取为同名的局部变量
  console.log(name, age);
}

// 数组解构
{
  const [first, second] = [10, 20, 30];
  console.log(first, second);      // 10 20
}

// 函数参数解构
{
  function greet({ name, age }: { name: string; age: number }) {
    console.log(`${name} is ${age} years old`);
  }
}
```

> **本章小结**：
> 1. 优先 `const`，需要重新赋值时才用 `let`，永远不要用 `var`
> 2. 类型名一律小写：`string`/`number`/`boolean`，不是 `String`/`Number`/`Boolean`
> 3. 用模板字符串（反引号 `` ` ``）做插值；用箭头函数写短回调；相等比较一律用 `===`

## 本章练习

### 练习 1：`const` 还是 `let`？

> **重要程度**：⭐⭐

下面的场景分别应该用 `const` 还是 `let`？为什么？

1. 一个不会重新赋值的最大值常量
2. 一个需要递增的计数器

::: details 查看答案
```typescript
const MAX = 100;    // 不重新赋值 → const
let counter = 0;    // 需要 counter++ → let
counter++;
```
原则：默认 `const`，确实需要重新赋值时才用 `let`。
:::

### 练习 2：模板字符串

> **重要程度**：⭐⭐⭐

用模板字符串把变量 `name` 和表达式 `2 + 3` 拼成一句话，输出应为 `Hello Alice, 2 + 3 = 5!`。

::: details 查看答案
```typescript
const userName = "Alice";
const greeting = `Hello ${userName}, 2 + 3 = ${2 + 3}!`;
console.log(greeting);  // Hello Alice, 2 + 3 = 5!
```
:::

### 练习 3：箭头函数

> **重要程度**：⭐⭐⭐

用箭头函数把 `[1, 2, 3]` 映射为 `[2, 4, 6]`（每个元素翻倍）。

::: details 查看答案
```typescript
const doubled = [1, 2, 3].map((n) => n * 2);
// [2, 4, 6]
```
:::

### 练习 4：`===` 与 `==`

> **重要程度**：⭐⭐

`5 == "5"` 和 `5 === "5"` 的结果分别是什么？实际编码中应该用哪个？

::: details 查看答案
- `5 == "5"` 为 `true`——`==` 会先做隐式类型转换再比较
- `5 === "5"` 为 `false`——`===` 要求类型也相同

实际编码**始终用 `===`/`!==`**，避免隐式转换带来的意外。
:::

### 练习 5：解构赋值

> **重要程度**：⭐⭐⭐

从对象 `{ name: "Alice", age: 25 }` 中提取 `name` 和 `age` 为两个变量；再从数组 `[10, 20, 30]` 中提取前两个元素。

::: details 查看答案
```typescript
const user = { name: "Alice", age: 25 };
const { name: userName, age } = user;   // userName = "Alice", age = 25

const [first, second] = [10, 20, 30];
// first = 10, second = 20
```
:::
